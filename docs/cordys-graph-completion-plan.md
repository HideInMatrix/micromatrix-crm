# Cordys 用户功能图收口计划

本计划用于收口用户确认的功能图：工作台、线索/线索池、客户/联系人/公海、仪表板，以及系统下的组织架构、角色权限、企业设置/企微配置。实施仍以 `CordysCRM/` 源码为第一事实来源，运行页面只用于交互验收。

## 当前结论

- 基础公共能力：组织架构、角色权限、租户隔离、数据权限、操作日志、模块菜单底座已具备。
- 图中销售模块：已有可运行页面和 API，但“存在”不等于与 Cordys 完整一致，仍需按模块逐页读取源码后复查字段、操作、权限、状态与关联数据。
- 企业设置：W3.1 已完成企微配置、安全凭据和连接测试；企微组织同步、统一登录和消息发送尚未完成。

## 执行顺序

| 阶段 | 范围                    | 完成标准                                                                               | 状态       |
| ---- | ----------------------- | -------------------------------------------------------------------------------------- | ---------- |
| W3.1 | 企业设置 → 企微配置底座 | 配置、AES-GCM 安全存储、连接测试、权限、审计、页面和自动化验收                         | `VERIFIED` |
| W3.2 | 企微组织同步            | 部门/成员差异预览、外部 ID 映射、冲突策略、同步执行与记录、失败重试和页面闭环          | `NEXT`     |
| W3.3 | 企微统一登录与消息渠道  | 外部身份/OAuth state、绑定与解绑、登录审计；消息渠道开关、发送器、重试与投递审计       | `PLANNED`  |
| W3.4 | 图中业务模块逐页复查    | 首页、线索/池、客户/联系人/公海、仪表板逐页完成源码→API→Service→数据模型→页面→测试闭环 | `PLANNED`  |

## W3.2 启动门槛

1. 先读取 Cordys 组织同步入口及 `ThirdDepartmentService`、`WeComDepartmentService` 全链路源码。
2. 在动页面前固化部门/成员映射、同步批次、差异与冲突的数据模型；DB-013 不得通过临时 JSON 或本地字段冒充完成。
3. 复用 W3.1 的企微凭据读取与连接验证，不把 Secret 传给浏览器或同步任务日志。
4. 组织同步必须在隔离租户验证新增、更新、禁用、重复执行、部分失败和映射冲突；完成后才能进入 W3.3。

## 长期完成约束

- 每个页面先读 Cordys 对应 Vue/API，再沿接口读取 Controller/Service/Domain/Mapper/迁移；公共依赖先于业务页面对齐。
- 当前阶段不实施但已发现的数据结构必须登记到 [暂缓能力与数据模型缺口台账](./cordys-deferred-backlog.md)，不能只写在聊天或提交说明中。
- 只有迁移、API、页面、权限、审计、自动化和浏览器验收均通过，阶段才能标记 `VERIFIED`。
