# 与 CordysCRM 的功能差距分析

> 对照基准：CordysCRM 社区版（v1.7，含 v1.4 标讯/报价/合同、v1.5 工商抬头/发票/回款、v1.6 订单/计算函数、v1.7 审批流）。
> 状态标记：✅ 已实现 · 🟡 部分实现 · ❌ 未实现 · ⛔ 明确排除（对应 Cordys 付费/企业版能力）

## 一、业务模块对照

## 三、基于本地实例的新发现（2026-08-13，来自 localhost:8081 前端资源的 API 面分析）

> 通过解析本地部署实例（v1.7+）前端 bundle 提取的真实接口路径（约 60 个模块前缀），发现以下**此前文档调研未覆盖**的能力。已按影响补入差距清单，逐模块的字段级/交互级对齐待后续登录实例逐一核对。

| 实例中的模块（API 前缀） | 能力推断 | 我们的现状 | 处置 |
| --- | --- | --- | --- |
| `lead-capacity` / `account-capacity` | 线索/客户**持有容量上限**（每人最多持有 N 条，公海体系组成部分） | ❌ 无容量概念 | 新增差距 → P1（并入公海规则设置） |
| `dict` | **数据字典**统一管理（选项集集中维护） | 🟡 选项分散在各字段 options 中 | 新增差距 → P2（字段引擎增加"引用字典"选项） |
| `announcement` | **公告管理**（多条/发布范围/已读） | 🟡 仅企业设置里单条公告文本 | 新增差距 → P2 |
| `user/api/key/*` | **API Key 管理**（多 key 列表/启停/删除） | 🟡 仅一次性生成 365 天令牌，不可管理吊销 | 修正差距 → P1（ApiKey 表 + 管理界面 + Guard 支持） |
| `system/auth-sources` + `sso/callback/oauth` | **SSO 认证源管理**（OAuth 等多认证源配置） | ❌ | 归入 P2 办公平台集成项 |
| `user/sync` | **用户同步**（从第三方目录同步组织架构） | ❌ | 归入 P2 办公平台集成项 |
| `export` | **导出中心**（疑似异步导出任务） | 🟡 同步 CSV 导出 | 观察项：数据量大后引入 BullMQ 异步导出（P2） |
| `search/config` + `global` | **全局搜索**（且搜索范围可配置） | ❌ | 已列 P1，补充"可配置搜索范围"要求 |
| `price` | **价格管理**（独立价格体系，疑似价格表/多价格） | 🟡 产品单一 price/cost | 新增差距 → P2（待实例核对具体形态） |
| `opportunity-rule` | **商机规则**（疑似阶段停留提醒/流转规则） | ❌ | 待实例核对后定级 |
| `attachment` | 附件系统 | ❌ | 证实存在，维持 P0 |
| `personal` | **个人设置**（自助改密等） | 🟡 无自助改密 | 证实存在，维持 P1（登录安全项） |
| `ui/display` | Logo/主题显示配置 | 🟡 | 证实存在，维持 P2 |
| `agent`（24 个路径） | AI 助手/Agent 对接界面在社区版有入口 | ⛔ 排除项 | 维持排除；商业化若需 AI 再评估 |
| `license` | 许可证管理（社区/企业版控制） | - | 不适用（我们无版本商业限制） |
| `locale-language` | 国际化 | ❌ | 维持 P3 |
| `contract/update/stage` | 合同也有**阶段**概念（非仅状态） | 🟡 我们是四态状态机 | 待实例核对（可能是合同审批阶段） |

> 已被实例证实与我们对齐良好的：`pool/lead-pool/account-pool`（池体系）、`follow`（跟进）、`custom-form/field/module`（表单配置三件套，对应我们的元数据引擎）、`approval-flow/approval-todo/approval-action/approval-resource`（审批四件套）、`business-title`（工商抬头）、`tender`（标讯）、`workbench/dashboard`（工作台）、`sse`（实时通知同样走 SSE）、`invoice/order/product/contract/opportunity/account(客户)/lead` 业务主模块。

## 四、差距汇总（按优先级）

- **P0（直接影响日常使用，优先补齐）**：附件系统、客户查重、客户 360 详情页、商机产品明细、商业标讯数据源接入（等 API 账号）
- **P1（体验与管理增强）**：操作历史、回收站、全局搜索（含范围配置）、目标管理、批量操作、线索查重、持有容量上限、API Key 管理、看板拖拽、合同到期提醒、打印模板、xlsx 导入导出、登录安全（含自助改密）、移动端补商机/合同
- **P2（锦上添花/商业化前）**：审批抄送加签、条件分支、计算函数库、数据字典、公告管理、客户标签层级、产品分类树、价格管理、编号规则、消息渠道与模板、异步导出中心、SSO/用户同步等办公平台集成
- **P3（暂不考虑）**：国际化
- **待实例核对后定级**：商机规则（opportunity-rule）、合同阶段（contract stage）、价格管理具体形态

实施排期见 [roadmap.md](./roadmap.md)。

3. 核对系统设置区全部页面（模块设置/公海规则/审批流/消息/字典/API Key）
4. 结论回写本文档状态标记与 [roadmap.md](./roadmap.md) 排期
