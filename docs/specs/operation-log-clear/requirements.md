# LOG-003 操作日志全量清空需求

## 1. 目标

在 LOG-002 已完成的租户级日志生命周期治理基础上，补充一个语义明确的“清空全部操作日志”能力，避免现有“立即清理”被误解为清空全部。

本执行单元编号固定为 `LOG-003`。

## 2. 需求

### R1 区分两个管理动作

- “清理过期日志”继续执行 retention 策略，只删除当前租户早于 cutoff 的操作日志。
- “清空全部操作日志”删除当前租户全部 `operation_logs`，不受 retentionDays 影响。
- 两个动作必须使用不同 API、不同按钮文案和不同确认提示。

### R2 租户与权限边界

- 全量清空只能作用于当前认证用户所属租户。
- 必须要求 `system:log:update` 权限。
- 不得影响其它租户操作日志、登录日志或其它审计数据。

### R3 风险确认

- 网页必须使用危险级二次确认。
- 确认文案必须明确“不可恢复”“仅当前组织”“全部操作日志”。
- 用户必须输入 `清空` 后才允许提交。

### R4 删除语义

- API 返回真实删除数量。
- 删除主日志时依赖现有 FK cascade 自动删除对应 `operation_log_blobs`。
- 全量清空接口本身不得通过 `@LogOperation` 再写回一条新的操作日志，否则“清空全部”语义不成立。
- 清空完成后前端必须刷新操作日志列表与策略状态。

### R5 安全执行

- 全量清空使用当前租户条件删除，禁止无 tenantId 的全表删除。
- 当前项目尚未正式上线，不需要为历史兼容增加额外数据迁移。

## 3. 不做范围

- 不清空 `login_logs`。
- 不增加跨租户平台级清空入口。
- 不提供定时“全部清空”。
- 不修改 LOG-002 的 retention/自动清理策略。
