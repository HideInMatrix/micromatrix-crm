# 招生 CRM 当前产品边界

本文描述当前产品应持续满足的业务边界，不是历史改造计划。实际 API、字段和页面行为以当前代码为准。

## 1. 产品主线

招生 CRM 围绕以下流程提供能力：

```text
线索获取 → 线索分配 / 线索池 → 跟进 → 转化客户 → 客户持续跟进
```

产品面向招生团队，保持领域模型通用，不把学校、课程、缴费、报名等特定业务写死在基础模型中；可变业务信息通过动态表单和外部系统集成承载。

## 2. 当前业务模块

| 模块     | 当前职责                                                                      |
| -------- | ----------------------------------------------------------------------------- |
| 线索     | 线索创建、分配、负责人、判重、SLA、跟进、导入导出和转化客户                   |
| 线索池   | 公海线索领取、移入、分配和自动回收规则                                        |
| 客户     | 客户资料、负责人、跟进记录、跟进计划及客户关系                                |
| 客户公海 | 客户入池、领取、分配、回收和库容规则                                          |
| 首页     | 线索与客户统计、转化趋势、渠道、负责人/部门绩效、客户结果及自定义字段分布分析 |
| 模块配置 | 线索/客户表单、动态字段、数据源、列表视图和业务规则                           |
| 外部事件 | API Key 接入、事件配置、幂等执行、线索转客户和客户动态字段更新                |
| 平台设置 | 用户、部门、角色、权限、企业集成、通知、公告、日志及个人 API Key              |

## 3. 领域与数据边界

- 线索与客户是两类核心业务资源；线索转化后关联客户，必要的跟进历史和附件按转换规则处理。
- 线索不再维护固定系统阶段/状态字段；需要招生业务分类时通过线索动态字段配置，不恢复旧的 `stage / status / lastStage` 系统字段。
- 线索与客户的可见范围遵循角色权限及数据范围；列表、详情、选择器和动作接口必须执行一致的服务端鉴权。
- 线索池与客户公海是正式业务能力。池内资源仍保留各自的业务状态和负责人/领取关系。
- 联系人不再作为独立模块或独立资源。线索联系人姓名、电话等信息属于线索自身字段；客户详情、转换、跟进记录和跟进计划不依赖独立联系人实体。
- 跟进记录和跟进计划只面向线索、客户，不得重新引入已退出的商机等目标类型。
- 业务扩展字段由动态表单管理；学校、渠道等可复用基础选项通过数据源提供。
- 缴费、报名、订单等交易事实由外部业务系统负责。CRM 不恢复商机、产品、报价、合同、回款、发票、订单或标讯交易链；需要同步的业务状态通过受控外部事件接入。

## 4. 平台与集成约束

- PC 管理端和企业微信 H5 移动端共享业务 API、权限规则和动态表单定义。
- 企业微信登录身份必须映射到当前租户的 CRM 成员；企业微信同步成员可禁用密码登录，不因此开放密码登录入口。
- API Key 用于服务集成，按创建用户的权限和数据范围执行；Secret 不得明文记录或返回给普通读取接口。
- 外部事件必须校验事件启用状态、调用凭证、资源定位唯一性、字段可写性和幂等键；业务写入与成功状态必须保持事务一致。
- 通知、操作日志、登录日志和外部事件审计属于平台能力，不应依赖已经退出的交易模块。

## 5. 明确不属于当前产品的能力

以下模块和概念不得作为当前开发需求或 API 依赖重新引入：

- 独立联系人模块及联系人关联流程；
- 审批模块；
- 商机、产品、报价、合同、回款、发票、订单和标讯等销售交易链；
- 商机阶段、赢单金额、回款金额等传统销售漏斗口径；
- 跟进计划/记录关联联系人或商机的能力。

如未来确有新业务需求，应重新评估领域边界、数据模型、权限和迁移方案，不得直接恢复历史实现。
