# ADMISSIONS-001 旧业务模块退出与数据清理审计

> 审计日期：2026-10-21
> 当前状态：旧业务模块代码及表结构已退出；历史配置清理通过独立 Prisma ORM 8 forward migration 处理。
> 适用范围：本文件记录当前主分支的最终边界与上线风险，不再作为旧销售模块的待拆解清单。

## 1. 当前产品边界

当前产品主线为 **线索 → 客户 → 持续跟进**。保留线索池、客户公海、跟进记录/计划、动态表单、首页统计、通知、组织权限、企业集成、导入导出及开放 API。

下列旧业务模块已从当前 API 注册、PC/Mobile 路由及 Prisma contract 中退出：

- 联系人独立实体及关联；
- 商机、产品/价格、报价、合同、回款计划/记录、发票、订单和标讯；
- 审批业务模块。

线索中的联系人姓名、电话等现有字段仍属于线索自身数据，不代表继续保留联系人实体。客户详情、线索转化、跟进记录和跟进计划不再依赖独立联系人记录。

- `20260928T0849_remove_legacy_sales_chain`：移除旧交易链相关表及线索旧产品字段。

## 3. 历史元数据清理原则

模块代码退出后，历史数据库仍可能留有导航、动态表单、保存视图、字典、阶段规则、消息设置和角色权限。当前清理仅针对已退出模块的元数据：

- 删除指向已退出资源的保存视图及其筛选条件；
- 删除已退出模块的系统表单元数据；
- 移除已失效的数据源类型与表单联动场景；
- 删除旧模块的导航、字典、阶段规则和消息设置；
- 从现有角色权限中剔除旧模块权限；
- 将旧模块尚未执行的导出任务标记为失败；
- 对主导航和顶部导航增加受支持 key 的数据库约束，防止历史 key 再次写入。

**不得借模块清理之名清空真实业务数据。** 清理迁移不得对线索、客户、跟进记录、通知历史、操作日志、登录日志、企业集成或管理员账号执行全表 `TRUNCATE` / `DELETE`。自定义表单数据、当前线索和客户字段（包括手机号）均应保留。

## 4. Seed 与测试数据边界

当前 `apps/api/src/prisma/seed-bootstrap.ts` 仅负责 Pro 套餐、必要消息设置、默认企业/根部门和首次安装管理员初始化；不再创建演示线索、演示客户、销售团队、销售主管或销售专员。检测到已有用户时，Seed 不会重建业务数据。

历史数据库里可能存在的旧测试业务记录不由初始化 Seed 自动删除。需要清理真实数据库数据时，必须先只读核对目标环境和精确记录范围，再单独制定可审计、可回滚的清理方案；不得复用旧版 SQL 中对整个线索/客户/日志表的清空语句。

## 5. 验收与部署风险

迁移文件完整性检查已通过，但本机 PostgreSQL `localhost:5432` 当前拒绝连接，因此尚未完成真实数据库的 `migration status` / `db verify` 验收。上线前需在目标环境执行只读状态核对，并确认历史模块 key、保存视图及角色权限的清理范围符合预期。

不得因本地数据库不可用而修改 `refs/db.json`、伪造 marker，或宣称数据库迁移已应用。迁移文件通过检查不等于真实数据库已经完成升级。
