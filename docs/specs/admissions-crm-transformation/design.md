# 招生 CRM 当前架构设计摘要

本文是当前实现的领域架构摘要。具体技术实现以代码、Prisma contract 和各专项设计文档为准；历史迁移过程通过 Git 历史追溯。

## 1. 核心领域

```text
Lead ──转化──> Customer
  │                │
  ├─ Lead Pool     └─ Customer Pool
  │
  └──── Follow-up / Follow-up Plan
                   │
                   └─ Attachment / Dynamic Fields
```

线索与客户是独立业务资源，分别具有列表、详情、负责人、数据范围和公海管理能力。转化流程负责建立线索与客户之间的业务关联，并按当前规则处理跟进记录、跟进计划和附件；不再创建交易资源。

## 2. 权限与可见范围

- 服务端权限是最终依据，前端隐藏按钮不能替代 API 鉴权。
- 线索和客户使用统一的角色权限与数据范围模型；本人、部门、自定义部门及全部范围按当前角色配置计算。
- 公海的查看、领取、分配、移入和回收分别校验对应动作权限及池规则。
- 首页“我的线索”等个人数据视图固定使用本人范围，不得因管理员具有更大数据范围而扩大个人工作列表。
- 线索与客户的列表、详情、候选选择器、导入导出和批量操作必须保持相同的数据范围约束。

## 3. 动态表单与数据源

线索、客户和跟进表单通过模块配置管理。字段定义、表单布局、移动端显示、字段联动、唯一性和数据源引用由统一表单能力承载。系统字段由后端能力规则保护；自定义字段按模块配置读写。

数据源用于维护学校等可复用基础资料，表单字段通过单选/多选引用数据源。数据源选择器应支持关键字检索和必要的虚拟化渲染。

## 4. 跟进协同

跟进记录和跟进计划的目标类型仅为 `lead`、`customer`。计划可按业务规则转换为跟进记录；评论、成员提及和附件属于协同能力。该领域不维护联系人关联，也不支持已退出的商机目标。

## 5. 外部事件

外部系统通过 API Key 调用外部事件执行入口。事件配置声明目标资源、匹配条件、字段映射和允许动作；服务端必须完成唯一资源定位、成员映射、字段权限和幂等校验。事件 Inbox 用于防止重复执行，业务写入和成功状态在同一事务提交。详细协议见 [外部事件文档](../../external-events.md)。

## 6. 平台能力

组织、成员、角色和权限提供租户内身份及数据范围基础。企业集成负责外部身份、组织同步和消息通道；通知、公告、操作日志、登录日志和事件审计独立于线索/客户业务模块。

## 7. 技术事实源

- 数据模型：`apps/api/src/prisma/contract.prisma`。
- Prisma 8 运行时 client：`apps/api/src/prisma/db.ts`，由 NestJS Prisma service/module 注入。
- Migration graph：`apps/api/migrations/`。
- 共享类型与权限定义：`packages/shared/`。
- PC：`apps/web/`；Mobile：`apps/mobile/`；共享浏览器能力：`packages/frontend-shared/`。
- 生产部署和数据库变更遵循 [Docker 发布文档](../../docker-release.md) 与 [Prisma 迁移规范](../../prisma-migration-policy.md)。
