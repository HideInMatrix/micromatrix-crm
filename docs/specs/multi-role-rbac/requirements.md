# 多角色 RBAC 与按权限合并数据范围

## 背景

本规格立项时，MicroMatrix CRM 的 `User.roleId` 只能给成员分配一个角色，与 CordysCRM 的 `UserRole` 多对多模型不一致；该差异现已按本规格完成迁移。当前实现使用 `UserRole` 多对多关联，并按权限码合并对应角色的数据范围，完成状态以 [tasks.md](./tasks.md) 为准。

## 目标

1. 成员可关联一个或多个角色，数据库不再保留 `User.roleId`。
2. 功能权限为所有角色权限码的并集，`*` 仍表示全部权限。
3. 数据范围按本次业务权限码计算：只有拥有该权限（或 `*`）的角色参与范围合并。
4. 任一参与角色为 `ALL` 时返回全部数据；否则合并 `DEPT`、`DEPT_AND_CHILD`、`CUSTOM` 部门范围，并始终允许本人负责的数据；只有 `SELF` 时仅本人。
5. `CUSTOM` 继续包含所选部门及全部下级部门；`DEPT` 为本部门；`DEPT_AND_CHILD` 为本部门及下级部门。
6. 成员管理支持 `roleIds` 多选；角色管理支持查看、批量添加和移除成员。
7. 审批角色节点、角色成员数、角色删除、种子数据、注册管理员和内部用户权限解析全部改用关联表。
8. 角色授权必须同时受功能权限上限和每个权限码对应的数据范围上限约束，非管理员不能利用另一个无关权限角色扩大授权。

## 非目标

- 不保留旧 `roleId` API 或数据库兼容字段。
- 不引入 Redis 权限缓存；当前由认证守卫按请求加载。
- 不迁移 Cordys 的 License、组织同步或第三方身份源。

## 验收场景

1. 一个成员同时拥有两个角色，登录返回两者名称与权限并集。
2. 角色 A 有 `menu:customer + CUSTOM`，角色 B 有 `customer:update + SELF`；客户列表可见 A 的部门范围，但编辑只能操作本人客户。
3. 给 B 增加 `customer:update + CUSTOM` 后，编辑范围合并扩大。
4. 成员编辑可多选角色；角色成员面板可添加/移除成员，成员列表与计数立即一致。
5. 删除非系统角色会删除关联关系、不删除成员；如果会导致成员没有角色则拒绝删除，系统角色始终禁止删除。
6. 无对应权限角色时，数据范围判定不可见；接口权限守卫仍返回 403。
