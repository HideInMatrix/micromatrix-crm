# 外部事件配置与 API 调用

外部事件用于将招生接待、缴费等外部系统的业务事件安全地同步到招生CRM。事件模板限定允许执行的模块、动作、定位条件和字段映射；调用方不能通过请求参数任意指定 SQL 或业务操作。

## 1. 管理入口与权限

管理入口：**系统 → 企业设置 → 外部事件**，页面路径 `/system/settings/external-events`。

- `system:setting`：查看事件模板。
- `system:setting:update`：创建、修改、停用、删除模板及执行只读模拟。
- 每个模板绑定一个当前有效的 CRM 用户/API Key 所属账号；正式请求必须使用该账号的 API Key。

新建模板时，CRM 自动生成 `eventType` 和内部来源标识。`eventType` 是调用方使用的稳定标识，不可修改；内部来源标识由服务端管理，不需要放入请求。

## 2. 配置流程

编辑器分为基本信息、目标模块、匹配配置、流程方案、字段映射和测试配置。

### 目标模块与动作

当前支持目标模块 `lead`、`customer`，动作如下：

| 动作             | 说明                                                                 |
| ---------------- | -------------------------------------------------------------------- |
| `update`         | 在目标模块中按定位条件唯一匹配记录，更新允许写入的字段               |
| `create`         | 创建线索或客户，不定位已有记录；记录名称由单独的名称参数提供         |
| `convert`        | 定位线索并转化为客户，可同时映射客户字段                             |
| `upsertCustomer` | 缴费成功同步：命中客户则更新，只有命中线索时则转化客户；不创建新客户 |

`convert` 只能以线索为目标；`upsertCustomer` 的目标必须为客户。

### 资源定位

普通 `update` / `convert` 使用目标模块表单中可精确匹配的字段，多个条件按 AND 组合，必须唯一命中。`create` 不需要定位条件。

缴费成功同步单独配置学生姓名参数、手机号参数，以及客户和线索各自的手机号字段。系统会同时检查客户与线索，使用精确匹配；出现多条记录或独立客户与未转化线索同时命中时拒绝执行，不任意选择。

### 字段映射

字段映射候选项直接读取当前租户的线索/客户模块表单，不维护独立的外部事件字段清单。仅当前存在、未隐藏且当前动作允许写入的字段可选；计算字段和子表格不可直接映射。保存模板时服务端会再次校验，字段被删除、隐藏或不再可写时必须重新配置。

- 记录名称通过 `nameExternalKey` 指定，不在普通字段映射中重复配置。
- 负责人通过独立负责人配置处理；线索转化时也可以把原线索负责人映射到客户的成员字段。
- 新增线索时可额外映射系统字段 `contact`（家长姓名）和 `phone`（家长手机号）；它们只用于创建线索，必须来自外部事件参数。
- 新增线索可使用 `__leadPool` 特殊映射目标，将外部值映射到已启用的线索池。它不是表单字段。配置外部负责人时必须同时配置线索池映射，负责人无法解析时按映射入池，不使用固定兜底池。
- `upsertCustomer` 的客户手机号字段必须映射到与身份匹配相同的外部手机号参数。

选项字段（单选、单选按钮、多选、复选）支持 `valueMap`。配置后严格按显式映射转换；未配置时，系统按完整字符串精确匹配 CRM 选项的 `label` 或 `value`。显示文字重复、值未匹配时返回字段级错误，不进行模糊匹配。

空值按目标字段必填规则处理：未传、`null`、空字符串或空数组视为空值；非必填字段跳过本次赋值，必填字段返回明确错误。定位参数、记录名称、缴费身份姓名/手机号和负责人/线索池路由参数仍按各自规则校验。

## 3. 调用接口

```http
POST /api/external-events/execute
Content-Type: application/json
X-Access-Key: YOUR_ACCESS_KEY
X-Secret-Key: YOUR_SECRET_KEY
```

请求体：

```json
{
  "eventType": "EVENT_由管理端生成的标识",
  "data": {
    "studentName": "王同学",
    "phone": "13800000000",
    "paymentStatus": "SUCCESS"
  }
}
```

`data` 中的参数名由管理员在模板中配置。新接入时以管理端「查看接口」生成的 cURL、JavaScript 或 Python 示例为准；不要自行假设字段名。

`externalEventId` 通常无需由调用方填写，省略时服务端自动生成。若上游系统本身具有稳定的业务事件编号，且需要依靠该编号安全重试，可在请求中传入；同一业务事件的每次重试必须使用相同编号和相同请求内容：

- 同一模板、同一编号、同一请求内容再次提交，返回已完成结果，不重复执行业务写入。
- 同一编号对应不同请求内容，返回 `IDEMPOTENCY_KEY_REUSED`。
- 事件仍在处理中时，返回 `EVENT_PROCESSING`；稍后可使用相同编号和相同内容重试。
- 未提供编号时服务端生成一次性编号；调用方若需要跨请求重试去重，必须使用上游稳定编号，不能在每次重试时重新生成。

模板配置内容发生变化时版本递增；仅启用/停用、改名或更换绑定账号不会因配置内容未变而递增版本。事件标识和内部来源标识保持不变。

## 4. 缴费成功同步规则

选择 `upsertCustomer` 后，按学生姓名和手机号同时匹配客户与线索：

1. **命中客户**：更新映射的客户字段，保留原负责人。若更新后的字段命中管理员配置的客户完结规则，客户原本位于客户公海时会按现有规则移出公海。
2. **未命中客户、命中线索**：将线索转化为客户，写入缴费字段并继承原线索负责人；无负责人时保持为空。
3. **客户与线索均未命中**：返回 `PAYMENT_TARGET_NOT_FOUND`，不创建客户、不执行业务写入。
4. **多条命中或跨模块冲突**：拒绝执行并记录失败原因。

缴费成功同步不支持指定新负责人。绑定的 API Key 账号必须具有客户和线索所需的全局数据范围；租户存在客户公海或线索池时，还必须具备相应池访问权限，避免因权限范围不足而漏判已有记录。

## 5. 业务通知

外部事件在业务事务成功提交后，复用 CRM 的消息设置和站内通知机制：

- `create` 新建线索时使用既有 `CLUE_ADD`（消息设置中的「新建线索」）；新建客户使用既有 `CUSTOMER_ADD`。因此外部事件与 PC 新建操作遵循同一开关。
- `update` 更新线索时使用「外部事件更新线索」通知，更新客户时使用「外部事件更新客户」通知。两项事件在消息设置中默认关闭，管理员可分别开启。
- 只有字段的实际存储值发生变化才发送更新通知；重复提交相同值、没有负责人或负责人就是 API 调用账号本人时不通知。
- `upsertCustomer` 命中已有客户并实际更新字段时，也使用「外部事件更新客户」通知；命中线索并转化时，继续使用既有「新建客户」和「转为客户」通知。
- 通知只在业务事务提交后发送。相同幂等事件重放直接返回已完成结果，不重复触发通知。

## 6. 模拟执行与审计

保存模板后可执行只读模拟：

```http
POST /api/external-event-templates/:id/preview
Authorization: Bearer <access-token>
Content-Type: application/json
```

请求体只包含 `data` 对象。模拟会检查资源定位、字段映射、选项值、权限和业务规则，不创建/修改线索或客户，也不改变负责人。正式执行仍会重新定位并检查并发状态。

正式调用审计位于**系统 → 系统日志 → 事件日志**。审计记录请求参数的脱敏快照、调用账号、事件编号、业务对象和执行结果；认证请求头和 Secret 不会作为业务参数保存。`ExternalEventInbox` 独立承担幂等控制，不受事件日志清理影响。

## 7. 兼容接口

以下接口保留给既有集成使用，新接入优先使用事件模板与 `/execute`：

```http
POST /api/external-events/customer-sync
X-Access-Key: YOUR_ACCESS_KEY
X-Secret-Key: YOUR_SECRET_KEY
```

该兼容接口使用 `source`、`where` 和 `set` 请求结构，按客户/线索定位并同步客户动态字段。不要将其与模板驱动的 `/execute` 请求结构混用。
